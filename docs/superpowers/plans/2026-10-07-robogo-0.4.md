Spec: `../specs/2026-10-07-robogo-0.4-design.md`. Branch `release-0.4`. Test first for every step.

1. **Sound.** Measure what plays (audio session peak meters). Core tests for `Get-RoboSoundName`, `Invoke-RoboSound`, the seam and the guard. Add `PlayEvent` to `RoboGo.Native`, route `Invoke-RoboAttention` through it. Measure again.

6. **Verify.** All suites on both hosts, self-test, smoke test, workflow run on the pull request, merge to `main`, tag `v0.4.0`, check the release.

## Execution notes

- Sound: `PlaySound` with `SND_ASYNC` returns true before anything is looked up, so `Invoke-RoboSound` cannot say whether a sound was played. The test only checks that the call into `winmm.dll` works; an event Windows does not know was measured to be silent.
- Sound, end to end: the window suite was run once with the real `Invoke-RoboSound` and a peak meter on the System Sounds session. Seven jobs ended (ok, warning, error), the meter showed sound at that time. Jobs that end within the same second cut each other's sound short; that is `PlaySound` behaviour and fine for a done signal.
- Texts: the full Polish names of the modes did not fit the options row. The new window test (every language, nothing clipped) caught it; the mirror became the short "mirror", and three check boxes got the short imperative.
- Texts: `en.json` differed from the built-in texts in four example texts, edited by Czak. They were taken over into the app.
- Single file: `@(Get-RoboLanguages)` wraps the returned array once more; the self-test takes the array as it comes.
- Single file: Windows PowerShell 5.1 started from PowerShell 7 can inherit a module path in which `Get-FileHash` is not found. The Package suite hashes with .NET.
- Workflow: the bridge to the PC refuses to write below `.github/workflows`, so the file was put there with a shell command.
- Signing: tried on a copy of the exe in TEMP with a throwaway self-signed certificate made by the OpenSSL of Git (never in the certificate store, deleted afterwards): no certificate gives exit 0 and a warning, a wrong password gives exit 1, a good one signs with a DigiCert timestamp, and the signed exe passes its self-test alone.
- Workflow, first run on GitHub (Windows Server 2025, elevated): two older tests failed. They made a copy fail by holding the source open without sharing; an elevated robocopy reads through that and copies the file. A probe run compared five ways to block a copy on the runner and on the PC; a lock on the bytes of the source fails in both (ERROR 33), so the tests use that now. Second run: green on both hosts, exe built and self-tested alone.
- Seen in the same probe, not followed up: with a destination folder that denies writing, robocopy on the PC printed ERROR 5 for the destination folder and still ended with exit code 0. Worth a look at what RoboGo says in that case.
- Not verified by anyone's ears: the sound was measured, not heard. Still open from 0.3: one taskbar button after pinning the running window.
