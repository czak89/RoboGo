# RoboGo 0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One taskbar button, neutral texts, Send to, remembered fields and recent paths, taskbar progress with a done signal, a failed-files view, a free-space check, a two-line command tape, remembered window placement, and the project files for a public repository.

**Architecture:** `RoboGo.ps1` keeps its sections. Section 0 gets a JSON writer and richer settings, section 1 the Send to shortcut and the free-space helper, section 2 the failure list, section 4 the new controls and one native helper type that replaces the small DWM import. The launcher passes its argument through an environment variable.

**Tech Stack:** PowerShell 5.1 and 7, WPF, `robocopy.exe`, C# 5 for the launcher and the native helper, git, GitHub CLI.

Spec: `docs/superpowers/specs/2026-10-07-robogo-0.3-design.md`

## Global Constraints

- Everything from the 0.2 plan still holds: both PowerShell hosts, ASCII-only files, invariant-culture numbers, structure-based parsing, tests confined to temp folders and `ROBOGO_HOME`, no em or en dashes, every text through `Get-RoboText`.
- No text contains a plural form or `(s)`. Counts read `Label: number.`
- Tests never show a dialog, play a sound, flash a button, touch the clipboard or the real Send to folder. They replace `Confirm-RoboGo`, `Invoke-RoboAttention`, `Set-RoboClipboard` and set `ROBOGO_SENDTO`.
- C# inside `Add-Type` stays within C# 5.
- Mode is never saved and never restored.
- Every commit message ends with the two attribution lines. Commits are made with the GitHub no-reply address.

### Task 1: Texts, settings, recents, Send to shortcut, free space, failure list

**Files:**
- Modify: `RoboGo.ps1`, `tests/Core.Tests.ps1`, `tests/Parser.Tests.ps1`, `tests/Engine.Tests.ps1`

**Interfaces:**
- Produces:
  - Texts: `verdict.*`, `log.scan`, `status.copyingErrors` in the neutral form of the spec. `Get-RoboVerdict` joins whole sentences with a space.
  - `ConvertTo-RoboJsonString [string]$Text` returns the quoted JSON string.
  - `Read-RoboSettings` returns `@{ Language; KeepLog; LogMaxDays; LogFileMaxMB; LogMaxMB; Window; Last; RecentSources; RecentDestinations }`. `Window` and `Last` are hashtables or `$null`, the recents are `string[]`.
  - `Save-RoboSettings [hashtable]` writes all of it; keys that are missing in the hashtable are left out or defaulted.
  - `Add-RoboRecent [string[]]$List [string]$Path [int]$Max = 10` returns `string[]`.
  - `Get-RoboLauncherPath` returns `RoboGo.exe` in the app folder when it exists, otherwise `RoboGo.cmd`.
  - `Get-RoboSendToPath`, `Test-RoboSendTo` (bool), `Set-RoboSendTo [bool]$On` (bool), `Update-RoboSendTo`.
  - `Initialize-RoboNative` loads the type `RoboGo.Native` once. `Get-RoboFreeSpace [string]$Path` returns bytes as `[long]`, or `-1`.
  - Parser state gains `Failures` (list of `@{ What; Code; Detail }`). `Get-RoboFailureLines $State` returns `string[]`.

- [ ] **Step 1: Write the failing tests.**
  - Core: the four example sentences of the spec through `Get-RoboText` and `Get-RoboVerdict`; no value in `$script:RoboText` matches `\(s\)`; `ConvertTo-RoboJsonString 'a\b"c'` gives `"a\\b\"c"` and a tab becomes `\t`; a settings round trip keeps `Last` (a UNC path, a name with a Polish letter, booleans, the text `abc` in `Threads`), `Window` and both recent lists; a file with `"Window": "x"` and `"Last": 5` gives `$null` for both; `Add-RoboRecent` puts the newest first, drops `d:\photos\` when `D:\Photos` comes in, ignores an empty path, keeps 10; with `ROBOGO_SENDTO` at a temp folder `Set-RoboSendTo $true` creates `RoboGo.lnk` whose target is `Get-RoboLauncherPath`, `Set-RoboSendTo $false` removes it, `Update-RoboSendTo` repairs a shortcut with another target and creates nothing when there is none.
  - Parser: the retry sequence of the existing test gives one failure with `What` = `Copying File C:\s\a.txt`, `Code` = `32 (0x00000020)` and the Polish message as `Detail`; a second file adds a second entry; `Get-RoboFailureLines` returns one line per entry that contains all three parts.
  - Engine: `Get-RoboFreeSpace` is above zero for the temp folder and for a folder below it that does not exist, and `-1` for a drive letter that is not in use; the locked-file job ends with one failure whose `What` ends with the file name.
- [ ] **Step 2: Run** Core, Parser and Engine on Windows PowerShell. Expected: Core fails at the first new text, Parser at `Failures`, Engine at `Get-RoboFreeSpace`.
- [ ] **Step 3: Implement.** The native type, loaded once:

### Task 2: Window

**Files:**
- Modify: `RoboGo.ps1` (section 4), `tests/Ui.Tests.ps1`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - Controls: `BtnSendTo, BtnRecentSource, BtnRecentDest, RecentPopup, RecentPanel, RecentList, BtnTape, TapeClip, BtnFailed`.
  - Seams: `Confirm-RoboGo [string]$Message` returns bool; `Invoke-RoboAttention [IntPtr]$Handle [string]$Level`.
  - `Initialize-RoboGoWindow $UI [-Source string]`, `Get-RoboGoLast $UI`, `Set-RoboGoLast $UI $Last`, `Save-RoboGoState [-Job]`, `Restore-RoboGoWindow $UI $Window` (bool).
  - `Show-RoboGoRecent [string]$Which`, `Select-RoboGoRecent [string]$Path`, `Clear-RoboGoRecent`.
  - `Switch-RoboGoFailed`, `Switch-RoboGoTape`, `Update-RoboGoTape`, `Switch-RoboGoSendTo`, `Set-RoboGoTaskbar [string]$State [double]$Value`.
  - `Set-RoboTaskbarIdentity $Window`, `Get-RoboTaskbarIdentity $Window` (string `id|command|name|icon`).

- [ ] **Step 1: Write the failing tests.**
  - restore: a settings file with `Last` and recents is written first; the new window shows every field from it, mode is COPY although nothing else is default; `-Source` of a folder fills FROM and empties TO, of a file fills FROM with its folder.
  - recents: both arrow buttons are enabled; `Show-RoboGoRecent 'Source'` builds one row per path plus the clear row; `Select-RoboGoRecent` fills FROM; a started job puts its two paths first in the lists and saves them; `Clear-RoboGoRecent` empties both and disables the buttons.
  - confirmation: with `Confirm-RoboGo` answering no a mirror does not start and the question contains both paths; answering yes it runs.
  - free space: with `Get-RoboFreeSpace` faked to 1,000 bytes and the answer no, the job ends after the scan with `Not started:` in the status line, nothing is copied and no working log is left; with yes it copies. The real free space is written into the log of an ordinary job.
  - taskbar: sweeping during the scan, normal with a value between 0 and 1 during the slow copy, none after a good end, error after the failing copy.
  - done signal: `Invoke-RoboAttention` is called once per finished job with `ok`, `warn` (cancel) or `error`.
  - failed view: a source file held open without sharing and RETRIES 0 gives `FAILED: 1`; the switch shows only that file and the button reads `FULL LOG`; back shows the whole log; a new job hides the button.
  - tape: with the long temp paths `SHOW ALL` is visible and the tape is two lines high; after the switch it is as high as the command and the button reads `SHOW LESS`; a short command hides the button.
  - placement: `Restore-RoboGoWindow` applies a rectangle inside the virtual screen and refuses one far outside; closing the window writes `Window` and `Last`.
  - identity: `Get-RoboTaskbarIdentity` returns `Czak89.RoboGo`, a command that ends with the launcher name, `RoboGo` and the icon path.
  - Send to: `Switch-RoboGoSendTo` creates the shortcut in the redirected folder and tints the button, a second call removes it.
- [ ] **Step 2: Run** the Ui suite. Expected: FAIL on the first missing control.
- [ ] **Step 3: Implement.** Order inside `Complete-RoboGo`: verdict, numbers, log file, failures, taskbar, attention, unlock. The free-space question sits in `Step-RoboGo` between the scan and the run, with the timer stopped while the question is open.
- [ ] **Step 4: Run** all suites on both hosts, then look at the renders (`ui-mirror.png`, `ui-running.png`, `ui-done.png`, `ui-failed.png`, `ui-recent.png`).
- [ ] **Step 5: Commit** `feat: recents, restore, failed view, taskbar progress, free-space question, Send to, taskbar identity, two-line tape`.
