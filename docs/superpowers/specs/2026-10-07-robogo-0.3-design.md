# RoboGo 0.3 design

- Date: 2026-10-07
- Status: approved in chat by Czak ("Build it", all nine features as presented).
- Builds on: `2026-10-07-robogo-0.2-design.md`. Everything not mentioned here stays as it is.

## Goal

Nine improvements that should land before the launcher is signed and the texts are translated, because they change the launcher or the texts: one taskbar button, neutral phrasing, Send to, remembered fields and recent paths, taskbar progress and a done signal, a view of the failed files, a free-space check, a shorter command tape, remembered window placement. Then the project files for a public repository.

## Decisions

| Topic | Decision |
|---|---|
| Mode | Never remembered. Every start is COPY, so a leftover MIRROR or MOVE cannot delete anything by reflex. |
| Done signal | Flashing taskbar button plus a Windows system sound, only when RoboGo is not the active window. |
| Send to | Opt-in through a toggle in the header. The shortcut in the Send to folder is the only thing RoboGo writes outside its own folder. |
| Plurals | No plural forms at all. Counts are written as `Label: number.` |
| License | MIT, `Copyright (c) 2026 czak89`. |

## 1. One taskbar button

The window lives in a PowerShell process, the pin points at `RoboGo.exe`, so Windows sees two programs. The fix is the documented one: the window gets an explicit AppUserModelID (`Czak89.RoboGo`) and relaunch properties (command, display name, icon) through its property store. A pin made from the running window then starts `RoboGo.exe` and shares the button with the window.

- Set before the window is shown, cleared when it closes.
- Relaunch command is `RoboGo.exe` when it exists, otherwise `RoboGo.cmd`. Icon is `RoboGo.ico`.
- A pin made from the exe file in Explorer keeps its own identity. The README says how to pin.
- Verified by reading the properties back. Whether the taskbar merges the buttons can only be seen by pinning; that check is Czak's.

## 2. Neutral texts

| Before | After |
|---|---|
| `Done. Copied 13 file(s), 6.6 MB, 2 skipped, 1 FAILED.` | `Done. Files copied: 13 (6.6 MB). Skipped: 2. FAILED: 1.` |
| `Would copy 4 file(s), 64.0 MB, 3 extra item(s) would be deleted from the destination.` | `Files to copy: 4 (64.0 MB). Extra items that would be deleted from the destination: 3.` |
| `Scan: 13 file(s), 6.6 MB to copy.` | `Scan done. Files to copy: 13. Data to copy: 6.6 MB.` |
| `Copying... 2 error(s) so far, see the log.` | `Copying... Errors so far: 2. See the log.` |

The verdict is built from whole sentences joined by a space, so a translator never has to keep a leading space or a comma. A test fails when any text contains `(s)`.

## 3. Send to RoboGo

- Header toggle `SEND TO`, amber when on. On creates `RoboGo.lnk` in the user's Send to folder, off deletes it. The state is whether the file exists.
- At start, an existing shortcut that points somewhere else (the folder was moved) is rewritten.
- The launcher hands its first argument to the app in the environment variable `ROBOGO_SOURCE`. No command-line quoting is involved, so `D:\` and names with spaces arrive intact. `RoboGo.cmd` does the same. `RoboGo.ps1 -Source` exists for direct use and tests.
- The app puts the folder into FROM and empties TO. A file gives its folder, as with drag and drop. More than one selected item: the first one counts.
- Tests redirect the Send to folder with `ROBOGO_SENDTO`.

## 4. Remembered fields and recent paths

`settings.json` gains three entries:

```json
"Window": { "Left": 100, "Top": 80, "Width": 760, "Height": 620 },
"Last": { "Source": "D:\\Photos", "Destination": "E:\\Backup", "Subfolders": true, "SkipJunctions": true, "OnlyNewer": false, "Restartable": false, "Threads": "8", "Retries": "2", "Wait": "5", "ExcludeFiles": "", "ExcludeDirs": "", "Extra": "", "Scan": true },
"RecentSources": [ "D:\\Photos" ],
"RecentDestinations": [ "E:\\Backup" ]
```

- `Last` is written when a job starts and when the window closes, and put back into the fields at the next start. Numbers are kept as typed.
- The recent lists get the paths of every started job: newest first, no duplicates (compared without case and trailing backslash), at most 10.
- A small arrow button next to each BROWSE opens the list. A click fills the field. The last row clears both lists.
- The file is written by the app's own JSON writer, so backslashes and non-ASCII names are escaped the same way on both PowerShell versions.

## 5. Taskbar progress and done signal

| Moment | Taskbar button |
|---|---|
| Scan, dry run, run without totals | sweeping |
| Run with totals | green, share done |
| Errors so far | yellow |
| Job failed | red and full, until the window is activated or the next job starts |
| Job ended otherwise | no progress |

When a job ends while RoboGo is not the active window, the button flashes until the window is activated and a system sound plays: Asterisk for a good end, Exclamation for a warning, Hand for an error.

## 6. Failed files

- The parser keeps every failure once: what robocopy was doing with which path, the error code, and the system message from the next line. Retries of the same file do not repeat it. At most 2,000 entries.
- `FAILED: n` appears under COPY LOG as soon as there is one. It switches the log box to the failures; `FULL LOG` switches back. COPY LOG copies what is shown.
- Each failure takes two short lines (what and where, then indented the code and the message), so nothing important ends up beyond the right edge of the log box.

## 7. Free space

After the scan and before copying, RoboGo asks Windows how much room the caller has on the destination (the nearest folder that exists, drive or share). The number goes into the log. If the job needs more, a question offers to run anyway: a mirror deletes first, and compression can make things fit. Declined means nothing is copied. Without a scan there is no total and no check.

## 8. Long commands

The tape shows two lines. When the command needs more, `SHOW ALL` appears under COPY and toggles to `SHOW LESS`, and three dots mark the place where the command is cut. The red warning line and the red edge do not depend on what the tape shows.

## 9. Window placement

Saved on close (the restore bounds when maximized or minimized, the height with the log shown), restored at start when at least part of it is on a screen. Size is never below the minimum.

## Seams for tests

Three small functions exist so tests can replace them and never touch the user's desktop: `Confirm-RoboGo` (every yes/no question), `Invoke-RoboAttention` (flash and sound), `Set-RoboClipboard` (from 0.2). `Get-RoboFreeSpace` is replaced in the window tests to fake a full disk.
