- Date: 2026-10-07
- Status: built on Czak's request of 2026-10-07 (fix the sound, review the Polish texts, release workflow with a single exe). He asked for the work to be carried through without further questions, so the decisions below were made on the way and are his to overrule.
- Builds on: `2026-10-07-robogo-0.3-design.md`. Everything not mentioned here stays as it is.

## 1. The done sound did not play

### What was found

Measured on Czak's PC (Windows 11 build 26300, sound scheme `.Default`, System Sounds at 100 percent, not muted) with the peak meters of the Windows audio sessions:

| Call | Result of the call | Peak in the audio sessions |
|---|---|---|
| `[System.Media.SystemSounds]::Asterisk.Play()`, PowerShell 7 | no error | 0.0000 |
| the same, Windows PowerShell 5.1 | no error | 0.0000 |
| `MessageBeep(0x40)`, `MessageBeep(0x10)` three times | `TRUE` | 0.0000 |
| `PlaySound("SystemAsterisk", SND_ALIAS or SND_ASYNC)` | `TRUE` | 0.27, session of the process |
| the same with `SND_SYSTEM` | `TRUE` | 0.27, System Sounds session |

### Root cause

RoboGo 0.3 played its done signal with `[System.Media.SystemSounds]`, which is a thin wrapper around `MessageBeep`. `MessageBeep` does not play anything in the calling process. It queues a request for Windows and returns success. On this system the request never becomes audio, although the sound scheme has a file for every event and nothing is muted. The call cannot tell: it reports success either way, and the `try`/`catch` around it had nothing to catch.

Why this build of Windows drops the request was not established; it is outside the app. The app no longer depends on it.

A second reason for silence is by design and unchanged: the signal is given only when RoboGo is not the active window (0.3 decision).

### Fix

RoboGo plays the sound itself: `PlaySound` from `winmm.dll` with the event of the sound scheme (`SystemAsterisk`, `SystemExclamation`, `SystemHand`) and the flags `SND_ALIAS`, `SND_ASYNC`, `SND_NODEFAULT`, `SND_SYSTEM`.

- The user's sound scheme still decides what is heard. An event without a sound stays silent.
- `SND_SYSTEM` puts the sound into the System Sounds entry of the volume mixer, where a user expects it.
- `SND_ASYNC` keeps the window responsive.
- New seam `Invoke-RoboSound`, replaced in the tests, so no test plays a sound.
- Verified with the same meter after the fix, through `Invoke-RoboAttention` on both hosts: peak 0.27 in the System Sounds session.

RoboGo is not a media player: there is no pause, resume, seeking or track change to check. What belongs to the same signal and was checked instead: the taskbar states (unchanged code, same tests), the flash, and that no sound plays for a job that never started.

## 2. Polish texts

- `lang/pl.json` is Czak's translation, reviewed against the English texts.
- `lang/en.json` (his rename of the old English-valued file) stays as the reference for translators. The app does not read it: English is built in, and a file named `en.json` is ignored on purpose. A test keeps it identical to the built-in texts. His four edited example texts in it (`ph.*`) were taken over into the app.

Terms, one per thing. The Polish words are in `lang/pl.json` under the keys named here (this file stays ASCII):

| English | Keys | What changed |
|---|---|---|
| FROM, TO | `ui.from`, `ui.to` | nouns for source and target in place of the bare prepositions, which gave sentences like "from the folder FROM"; every text now says source folder and destination folder |
| COPY, MIRROR, MOVE (modes) | `ui.copy`, `ui.mirror`, `ui.move` | the mirror button says "mirror", the short form of the "mirror copy" (Microsoft's term) that the warnings speak of; it was "copy 1:1" on the button. The full term does not fit: the options row overflowed, which the new window test caught |
| COPY (clipboard), COPY LOG | `ui.copyCommand`, `ui.copyLog` | the same verb form in both |
| switch | `ui.helpSwitches`, `tip.extra`, `problem.*` | Microsoft's word for a command-line switch; the word for "options" is left to the OPTIONS section |
| setup | `ui.helpSetups`, `ui.helpSetupNote`, `tip.help`, `setup.default` | one word, it was three different ones |
| junction | `ui.junctions`, `tip.junctions` | Microsoft's term |
| DRY RUN | `ui.dryRun`, `dialog.confirmTip`, `status.dryRun`, `verdict.dry` | the word on the button, in every message |
| Ready. | `status.ready` | the old word read as "done" |
| FAILED | `ui.failed`, `verdict.failed` | "failed items", it said "errors" |
| extra items | `verdict.extras*`, `tip.mirror` | "surplus", because the old word is also the name of the EXTRA field |
| ETA, TOOK | `ui.eta`, `ui.took` | "remaining" and "time" |
| WAIT S | `ui.wait`, `tip.wait`, `problem.wait` | "pause (s)" |
| BROWSE | `ui.browse` | as in Windows |

Style: tooltips and help lines describe in the third person, as Windows does. Check boxes use the short imperative, as the SKIP labels do. No dash characters. Menu names in Polish quotation marks.

A window test renders every language of the repository and fails when a control sticks out of the window.

Mistranslations fixed: `ui.newer` said "save newer files"; `ui.helpSetupNote` spoke of CPU threads; `status.copyingErrors` had lost "see the log"; `help.j` had lost "very"; `help.is` had lost "again".

## 3. One exe

Decision: the release is one file, `RoboGo.exe`, about 300 KB.

- `build.cmd` adds `RoboGo.ps1`, `RoboGo.ico` and `lang\*.json` to the launcher as resources.
- The launcher starts a `RoboGo.ps1` next to it when there is one (the repository folder, as before). Otherwise it unpacks its resources to `%TEMP%\RoboGo\app-<hash>` and starts that copy. The hash covers every name and byte, so each version has its own folder; folders of other versions are removed.
- Every start compares the unpacked files with the ones in the exe and rewrites what differs. A changed file in TEMP never runs.
- The launcher passes its own path in `ROBOGO_EXE`. The app then keeps settings and logs next to the exe, uses the exe as launcher and icon for the taskbar pin and the Send to shortcut, and offers the unpacked languages besides a `lang` folder next to the exe.
- `RoboGo.exe /selftest` runs the app's self-test, passes on its output and exit code. The `Package` suite and the workflow use it on a copy of the exe that sits alone in an empty folder.

Not chosen: a zip of the folder (two steps for the user), a compiled PowerShell host (PS2EXE and the like: a dependency, and virus scanners dislike them more), feeding the script to PowerShell through standard input (multi-line code breaks, `$PSScriptRoot` is empty).

Known cost: an unsigned exe that unpacks a script and starts PowerShell hidden is what a virus scanner looks at twice. Windows Defender on the build PC accepted it. SmartScreen asks at the first start of an unsigned download.

## 4. Release workflow

`.github/workflows/release.yml`, two jobs.

- `build` (Windows, read-only token): version check, all suites on both PowerShell hosts, `build.cmd`, signing, self-test of the finished exe alone, SHA-256 file, build artifact.
- `release` (only for a tag, the only job with `contents: write`): attaches `RoboGo.exe` and `RoboGo.exe.sha256` to the GitHub Release of the tag, creating it with generated notes.

Triggers: a tag `v*` publishes. Pushes to `main`, pull requests and manual runs build and test only. The tag must equal `v` plus the version in `RoboGo.ps1`.

Signing: `tools/Sign-RoboGo.ps1` with `Set-AuthenticodeSignature` (SHA-256, timestamp). The certificate comes from the secrets `SIGN_PFX_BASE64` and `SIGN_PFX_PASSWORD`, is loaded in memory and never written to disk. The step runs for tags and manual runs only. Without the secrets the build is unsigned and says so in a warning. No certificate exists yet, so releases are unsigned until Czak adds one.

## Testing

- Core: sound event per level, the call into `winmm.dll`, the signal uses the seam, a guard against `SystemSounds` and `MessageBeep`; language lookup for the single-file exe; every `lang/*.json` parses, has the keys, placeholders and leading switches of the English texts, and `en.json` equals them.
- Package (new): build, version of the exe equals the version of the app, self-test in the repository folder, self-test alone in an empty folder (unpacked below TEMP, data folder next to the exe, languages there, nothing written next to the exe), repair of a changed and a deleted unpacked file.
